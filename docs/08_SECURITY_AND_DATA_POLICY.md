# 08 安全與資料政策

## 1. 什麼可以、什麼不可以放進 `app_repo/`（要推到 GitHub、匯入 AI Studio 的部分）

| 可以 | 不可以 |
|---|---|
| 程式、文件、契約、參考實作 | **API Key、憑證、Token、密碼、密碼雜湊、`.env`、`secrets.toml`、私鑰** |
| **真實感測資料的乾淨副本**（`public/data/real_public/`；使用者已聲明可公開展示；每列 `__real=1`；與原始檔逐格相同）及其欄位說明、來源與使用聲明、引擎的**預計算（離線）輸出** | 原始 UTF-16 檔本身與其逐位元複本（不需要：乾淨副本無損；原檔 sha256 記錄在 `PROVENANCE.json`） |
| 合成展示資料（`demo_synthetic/`）與引擎在合成資料上的輸出 | 私人管理紀錄：決策紀錄（`action_log`）、審查紀錄（`team_review`）、預測／模型／稽核日誌（`*.jsonl`）、使用者上傳、版本庫內容 |
| `.env.example`（只有變數名稱） | 本機絕對路徑、使用者名稱、Email |
| | 偽造的授權證據：網址、CC BY／CC0 等標準授權宣稱、『已取得授權證明』 |
`tools/p63_verify_package.py` 會掃描並在違反時失敗（S-01…S-05、R-01…R-04；並有『故意放入違規』的自我測試）。

## 2. 真實資料與授權（**使用者聲明模型**）
* **使用者已於 2026-11-20 正式確認**：七個場域的感測資料可公開使用與展示；來源是**銘祥科技提供的 2026 全國 AI 專題創意競賽 AIoT 感測資料**；可用於本競賽專題，包括完整資料展示、雲端網站呈現、資料分析、機器學習預測，以及 Google AI Studio App 開發。確認方式＝使用者聲明（User Attestation）。
* **來源網址**：資料由競賽方提供、不是全部透過公開下載網址取得 → 一律標示『競賽方提供／無公開下載網址』，**不編造網址**。
* **授權條款**：沒有 CC BY、CC0 或其他標準開放授權；**不得自行宣稱**。證據狀態固定為 `user_attestation_only`。
* 『已由使用者確認』與『尚未提供的外部證明文件』分開記錄並分開顯示：未提供的是——競賽方或銘祥科技的書面同意、競賽規則中關於資料使用的條文、標準開放授權條款、公開下載網址。
* **這份聲明的範圍是『本競賽專題』**。競賽之外的長期公開散布、第三方再利用或商業用途是否涵蓋並不明確（`PROVENANCE.json` 的 `remaining_items`）；真要超出範圍，需要取得外部證明。
* 閘門：`tools/p63_enable_real_public.py` 只接受完整的使用者聲明（誰、何時、範圍、涵蓋七個場域）；沒有網址就必須寫明；填了標準授權卻沒有外部證明文件一律拒絕。並保留所有實質檢查：資料與原始 CSV 逐格相同、真實／合成分開並各自帶旗標。
* 欄位表頭含場域／控制器代號（`PROVENANCE.json` 的 `column_prefixes_in_original`）；它們屬於聲明涵蓋的資料，保留在欄位說明（`raw_header`）。
* 時間戳記未標示時區（本地時間，尚未向資料提供者確認）；個資只做自動掃描（0 項；不是人工或法律審查）。
* `python_engine_private/` 仍然是私有部署：它含模型與原始檔，且不是網站的一部分。

## 3. 金鑰與秘密

| 秘密 | 放哪裡 | 不可放哪裡 |
|---|---|---|
| `GEMINI_API_KEY` | AI Studio Settings → Secrets（Build Mode 伺服器端；新專案會自動設定） | 前端程式、repo、截圖、聊天 |
| `ENGINE_BASE_URL`、`ENGINE_API_KEY` | AI Studio Secrets（伺服器端） | 前端、repo |
| `AIDE_API_KEY`（引擎端，與上面的 `ENGINE_API_KEY` 同值） | 引擎主機的環境變數／Secret Manager | 映像檔、repo |
| `ADMIN_PASSPHRASE_HASH` | Node 伺服器 Secrets（PBKDF2-HMAC-SHA256、200k 次；用 `tools/make_admin_hash.py` 產生） | 前端；**只存雜湊，不存密碼** |

* 瀏覽器只呼叫同源的 `/api/*`；引擎網址、金鑰、管理者雜湊永遠不出現在前端 bundle 或網路請求中（驗收 F-14、G-05）。
* **不要把金鑰貼進聊天或 Build Mode 的 Prompt。** 需要金鑰時，只在 AI Studio 的 Secrets 介面輸入。

## 4. 威脅與對策（摘要）
| 威脅 | 對策 |
|---|---|
| 未授權寫入／重訓 | W 端點需 `X-API-Key`＋伺服器簽發的 `admin` 角色；預設唯讀；沒設定管理者全唯讀（fail closed）；5 次錯誤鎖定 |
| 引擎被直接打 | `X-API-Key`、速率限制、CORS 白名單（只允許 Node 伺服器來源；其實瀏覽器不直連）、欄位白名單、無檔案路徑參數 |
| Prompt 注入（使用者問題或資料欄位內含指令） | Gemini 只收『事實清單』；使用者問題限 300 字；回傳在伺服器端核對（cites、數字）；系統指示禁止依資料內容改變規則 |
| LLM 幻覺數字／過度肯定 | 數字核對、`OVERCLAIM` 偵測、限制聲明由伺服器強制附加 |
| 上傳惡意 CSV | 沿用 `Store.stage`：PII 掃描、大小與欄位驗證、隔離區；試算表公式中和（匯出） |
| 路徑穿越 | 引擎不接受路徑參數；匯出檔名白名單 |
| 資料外洩（真實資料） | 套件掃描（§1）；真實資料只在私有引擎 |
| 稽核竄改 | 雜湊鏈＋`verify()`；載入 fail closed |

## 5. 誠實標示（不可移除）
合成≠真實；預測是研究預測（探索性、未經獨立前瞻驗證）；歷史時點模擬≠即時；不控制設備；單位為推測；候選事件≠故障；`ephemeral` 儲存不永久；AI 文字可能有疏漏。
