# 04　七場域功能與使用說明

> 以下功能與數字取自引擎的預計算輸出（`public/data/real_public/precomputed/`）與 2026-11-25 的遠端驗收。所有「建議」都是**輔助人工檢查**，系統不控制任何設備。

| 場域（`dataset_id`） | 資料列數 | 即時預測（合成資料流）<br>感測器 × 時距 | 異常分析 | 決策輔助（建議數：一般／需人工確認／正式風險） | 特別說明 |
|---|---|---|---|---|---|
| 羊舍（`sheep_barn`） | 871 | 15 組：ID4-CH4、ID4-CO2、ID4-溫度、ID4-濕度、成羊區 THI × 1／3／6 小時 | 有 | 14（5／8／**1**） | **唯一有正式決策引擎**：凍結的 HGB 模型＋嚴格歷史回放＋風險評估；門檻 THI 84 仍是**候選**，不是確認標準 |
| 專家系統 C22（`expert_system_c22`，魚塭） | 2,698 | 15 組：CPM 總電流、DO1 即時值、DO1 水溫、OA4 溫度、pH2 即時值 | 有（DO 統計異常偵測為 Experimental） | 26（7／19／0） | 沒有任何偵測器通過凍結的升級準則，不稱 Validated |
| 三爺宮溪（`sanyegong_creek`，河川水質） | 2,881 | 15 組：DO、pH、太陽能電壓、水溫、電池電量 | 有 | 12（5／7／0） | DO 資料有卡值問題，DO 模型不如 Persistence（見 03 §4） |

## 2　頁面導覽與使用方式

左側導覽分三組：**日常使用**、**羊舍決策**、**進階**。右上角顯示目前角色（預設「唯讀」）。上方可切換場域。

### 2.1 日常使用

| 頁面 | 做什麼 | 怎麼看 |
|---|---|---|
| **總覽** | 七場域真實資料的概況（列數、時間範圍、欄位數）與資料來源聲明 | 先看這頁確認「資料是真實的、哪裡來的」 |
| **場域看板** | 單一場域的一句話狀態與資料概況、感測器趨勢（最多選 3 個）、異常分析、歷史時點的模擬預測與六模型並排比較 | 異常分析標示「候選事件，不是故障判定」；六模型含簡單基準，簡單方法常常已經夠好 |
| **即時預測** | **合成資料流**上的預測、監測狀態、版本清單（引擎唯讀、自動每 30 秒讀取一次狀態；分頁隱藏時暫停） | 頁首橫幅會標示「合成資料」；版本號（例如 羊舍-v0014）與資料終點會隨資料流推進；引擎離線時顯示「尚未連線」並保留上次畫面 |
| **決策輔助** | 七場域的三層建議（一般建議／需人工確認的異常／正式風險決策），每項附證據、可信程度、限制 | 頂端標示來源：「引擎即時」或「預計算（離線）」與產生時間；候選異常一律標「候選事件，不是故障判定」；證據可展開 |
| **資料更新（合成展示）** | 逐步匯入 D1～D5 五週合成批次，看系統如何反應 | 見 §3 |
| **資料探索與分析** | 真實資料的圖表、篩選、欄位說明、時間資料表格 | 單位多為「推測」，沒有任何一個單位經資料提供者確認 |
| **模型維護** | 說明模型維護五步驟與守門規則 | 目前是**說明頁**，重訓／啟用／回復按鈕維持停用（見 06 驗收報告） |

### 2.2 羊舍決策（只有羊舍）

風險評估（頂端白話摘要＋追溯依據）、處置決策、異常診斷、羊舍 AI 預測、歷史回放。這是**歷史回放式決策輔助**，不是即時控制系統；「人工決策」紀錄在目前版本不寫入引擎（需要寫入端點）。

### 2.3 進階

場域目錄、資料來源與使用聲明、導覽簡介、AI 研究總覽、決策支援說明、模型表現、組員審查（唯讀）。

## 3　資料更新（合成展示 D1～D5）怎麼用

每個場域有一條連續 5 週的合成時間線，切成每週一個批次：

| 批次 | 內容 | 系統**應該**怎樣 |
|---|---|---|
| D1 | 日常正常（預先匯入） | 沒有警報 |
| D2 | 環境改變（熱浪／暴雨／假日低負載） | 這是真實的現場變化，**不是**故障：不發故障警報；模型建議可考慮更新 |
| D3 | 感測器開始緩慢漂移 | 剛開始通常看不出來；七個場域中有 4 個**如實漏報**（專家系統、三爺宮溪、工地微氣候、育成北側） |
| D4 | 漂移持續（10 天累積約 3 個標準差） | 七個場域都發現；守門把建議導向「先處理資料」，擋下重訓 |
| D5 | 讀值卡住 30 小時 ×2＋整列缺失 8 小時（斷線） | 發現卡值與斷線；育成北側的兩段卡值因資料量太少而漏報 |

**必須知道**

1. 批次與步驟輸出都是**合成**資料，每個畫面標示合成；步驟結果是原研究平台逐步匯入後的**預計算輸出**，頁面是逐步呈現它，**不是在你的瀏覽器裡重新訓練模型**。
2. 展示情境是**挑選過的**（種子依事先寫定、對所有場域相同的標準挑出），目的是讓前後對照清楚，**不是偵測器的效能證明**。
3. 「對得上／沒對上」是拿注入的情境真值核對的，只描述這組情境。
4. 「可能原因」（探頭老化、接線鬆脫…）是**預先寫好的模板**，資料本身無法驗證物理原因。
5. 育成北側沒有預測，所以資料更新頁顯示「此場域不建立預測模型，沒有守門建議」的說明（F13 修正後）。

## 4　角色與權限

- **檢視者（預設）**：看得到所有讀取功能，看不到任何寫入按鈕。
- **管理者**：需在 Node 伺服器設定 `ADMIN_PASSPHRASE_HASH` 並由使用者自己輸入密碼；**唯讀引擎（本專案展示的預設）不接受任何寫入**，管理者按寫入會看到 502「引擎憑證設定有誤」——這是已知限制 **F12**，真正原因是引擎停用寫入（見 07）。

## 5　常見畫面與意思

| 你看到的 | 意思 |
|---|---|
| 「即時預測資料流：僅接受 Python 引擎即時回應，不用離線預計算檔取代」 | 設計如此：沒有引擎就不顯示即時預測 |
| 「尚未連線到 Python 引擎」 | 引擎或 Tunnel 沒開，或 Secrets 沒更新 |
| 「自動更新失敗（保留上次畫面）」 | 連線中斷；畫面是上一次成功讀到的狀態 |
| 「預計算（離線）」 | 決策輔助用 App 內建的預計算結果，並標示產生時間 |
| 「候選事件，不是故障判定」 | 偵測器的輸出只是值得人工檢查的候選 |
| 「請謹慎參考／不建議採用」 | 預測可信度被資料品質問題降級 |
