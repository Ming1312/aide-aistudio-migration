# 03　AI 模型、研究方法與驗證結果

> **讀這份文件前請先記住三件事**
> 1. 所有真實資料的預測結果都是**時間序列回測（walk-forward backtest）**，屬於**探索性**結果。資料在多個階段被反覆檢視過，**沒有任何一筆是真正未看過的盲測資料**，所以沒有任何模型被稱為 Validated。
> 2. 以合成資料得到的數字（異常偵測、守門）只描述「偵測器在這個合成產生器上的表現」，**不是真實現場的故障辨識能力**。
> 3. 風險門檻 THI 84 是**候選分析門檻**，不是資料提供者或負責單位確認的熱緊迫標準。
>
> 數字來源：各階段報告（`outputs/phase2…phase5_9/`，位於原研究專案；下表標出報告名稱）。本文件沒有重新計算任何數字，也沒有重新訓練任何模型。

## 2　研究方法原則（貫穿所有階段）

| 原則 | 做法 |
|---|---|
| 先寫規則再看結果 | 每個實驗先把協定（切分、特徵、判定標準）寫在 `protocol.md` 或程式 docstring，再跑一次；不依測試結果反覆挑模型 |
| 嚴格的時間切分 | 絕不隨機打亂；擴張視窗 CV＋隔離區（purge）；訓練標籤時間必須早於測試起點；Holdout 只評估一次 |
| 洩漏稽核 | 因果性測試（把 t 之後的資料刪掉或改成 1e6，特徵必須不變）、標籤對齊、缺口測試、偵測器自我測試（故意放洩漏要抓得到） |
| 每個 skill 標明基準 | 不只對 Persistence 報喜；一律也對 Seasonal Naive、日夜基準（DiurnalDelta）報告 |
| 勝負規則 | CV 平均與 Holdout 同向較低才算贏，否則「分不出」；不做多重比較校正時明講 |
| 不確定度 | 24 小時區塊 bootstrap（相鄰小時高度相關，不當獨立樣本） |
| 誠實標示 | 看過結果後做的選擇、事後分析、樣本太少的結論，都在報告裡標成探索性 |

## 3　羊舍 THI 3 小時預測（Phase 2 → 2.6）

**任務**：預測成羊區 THI(t+3h)；模型實際預測變化量 `THI(t+3) − THI(t)` 再加回。候選模型：HistGradientBoosting（HGB）、XGBoost、Ridge；基準：Persistence、Seasonal Naive（昨天同一時刻）、DiurnalDelta（同一小時的平均變化）。

### 3.1 Phase 2：模型比較（報告：`phase2/model_comparison_report.md`）

Holdout（180 筆，只評估一次）MAE（THI 單位）：

| 方法 | MAE | 對 Seasonal Naive 的 skill |
|---|---|---|
| Persistence（現在不變） | 1.493 | −0.203 |
| Seasonal Naive 24h | 1.241 | 0 |
| DiurnalDelta（同小時平均變化） | 0.975 | +0.214 |
| HGB | 0.924 | +0.255 |
| XGBoost | 0.902 | +0.273 |
| Ridge | 0.902 | +0.273 |

- 5 折 CV（357 筆）：HGB MAE 0.913；Seasonal Naive 1.234；DiurnalDelta 0.957；HGB 5/5 折勝 Seasonal Naive（skill +0.260，bootstrap 95% 區間 [+0.02, +0.42]，區間很寬）。
- **誠實結論**：模型贏過 Persistence 與 Seasonal Naive，但相對「同小時平均變化」只好約 5%（HGB 對它的區間 [−0.01, +0.12] 含 0）——**模型學到的主要是日夜週期**。額外感測器、風扇、捲簾特徵組的 CV MAE 差距（0.913～0.916）小於雜訊。
- 資料洩漏稽核全部通過；刻意加入洩漏特徵時 Holdout skill 飆到 +0.94（正常 +0.38），作為「結果好得不合理就該懷疑」的對照。

### 3.2 Phase 2.5：風險感知框架（報告：`phase25/phase25_report.md`）

加入三項改良：感測器可信度模組、分位數／CQR 預測區間、超標機率與風險等級。540 個樣本外時間點（7 個 walk-forward 窗口）：

| 項目 | 結果 | 備註 |
|---|---|---|
| 預測區間覆蓋率 | 名目 90% → 實測 **0.900**（Phase 2 的區間名目 90% 只覆蓋 0.865）；平均寬 4.46 THI | 下午時段只覆蓋 0.83；各 3 天窗口在 0.83～1.00 間跳動 |
| 高 THI 漏報率（門檻 84） | 0.307 → **0.078**（事先宣告版）／0.118（部署版） | recall 差 +0.23，95% 區間 [+0.16, +0.30] |
| 誤報率 | 0.093 → 0.261／0.168；警報次數 142 → 242／200 | **這是用誤報換漏報，不是免費的改善** |
| 對 DiurnalDelta 的 MAE skill | +0.054，區間 [+0.003, +0.108] | 勉強排除 0 |
| 感測器可信度模組 | 人工模擬的 THI 通道故障（卡值、突跳、漂移、錯誤碼）偵測率 100% | **只在人工模擬情境驗證**；「上游溫度漂移但 THI 一致變動」只偵測到 81.5% |
| 警報 vs 只看時段的氣候機率警報 | **無法證明顯著較好** | 不能宣稱模型式警報優於「只看時段」 |

### 3.3 Phase 2.6：有限資料下的改良嘗試（報告：`phase26/phase26_report.md`）

事前宣告的保留標準（MAE skill 的 CI 下界 > 0 且至少 5/7 折較好）下，**沒有任何改良通過**：日夜基準＋殘差模型整體 MAE 比 Phase 2.5 差 1–4%；未來 3 小時最高 THI 模型沒有證據勝過。**正式模型維持 Phase 2.5，不替換。** 警報線只靠 5 天內層資料選擇，各折實際 FPR 從 0.03 變動到 0.25——這是目前最大的實務風險。

### 3.4 LSTM 探索（報告：`lstm/lstm_report.md`）

numpy 手寫 LSTM（梯度檢查最大相對誤差 3.6e-7），規則事先固定、只訓練評估一次：CV MAE 0.951（HGB 0.913、XGB 0.915）、Holdout 0.914（HGB 0.924、XGB 0.902）；配對 bootstrap 區間全部含 0。**沒有證據顯示 LSTM 優於樹模型**；樣本只有 238–526 筆訓練資料，結論受資料量限制。

## 4　其他場域：XGBoost vs HGB（報告：`other_sites/xgb_vs_hgb_report.md`）

七個預測任務（專家系統 DO1／OA4 溫度、三爺宮溪水溫／DO、工地溫度、東北角 TEMP、育成一廠 TEMP；育成北側因樣本不足未評估）：**XGBoost 贏 2、HGB 贏 1、分不出 4**；平均相對差 CV −0.06%、Holdout −0.31%，實質為 0。三爺宮溪 DO 的模型在 CV 與 Holdout 都不如 Persistence，反映資料品質問題（卡值）而非模型優劣。

## 5　通用感測器基準與資料量研究（Phase 5.6、5.7）

**Phase 5.6**（`phase5_6/phase5_6_report.md`；CONDITIONAL PASS）
- 七場域用完全相同的程序剖析：124 個欄位、93 個連續量測。
- 372 個候選任務（124 欄位 × 1／3／6 小時）→ 129 通過、93 有條件通過、150 不適合（多為狀態碼／計數器）。預算限制下評估 105 個任務。
- **105 個任務中只有 24 個（23%）達到預先登記的 ML 三項條件，81 個保留基準**；沒有任何單一基準通吃（最佳基準：線性自迴歸 50、持續性 27、季節性 Naive 22、移動平均 6）。
- 協定在評估前以雜湊凍結；洩漏稽核十類程式層面全部 PASS，另揭露兩項語意風險（時間戳語意、導出變數 THI）。

**Phase 5.7**（`phase5_7/phase5_7_report.md`；CONDITIONAL PASS）
- 90 個任務有學習曲線：HGB 隨資料增加改善 67、舊資料反而更差 13、無明確幫助 10；但**使用最多資料時基準領先 ≥5% 的有 35/90、ML 領先 ≥5% 的有 33/90**——增加資料不等於 ML 會超越基準。
- 滾動起點：預設用全部歷史（擴張窗口）通常不吃虧（沒有明顯差異 44、擴張較好 39、滑動較好 7）。
- 資料漂移旗標**過於敏感**：78/90 個任務被標為漂移候選，其中 44 個沒有表現退化的證據（資料漂移 ≠ 概念漂移）。
- 預測區間：105 個任務中 42 個 `UNCERTAINTY_NOT_VALIDATED`。

## 6　異常偵測與資料品質（Phase 5.2、5.8.7）

**專家系統 DO 統計異常偵測**（Phase 5.2，`phase5_2/phase5_2_report.md`；CONDITIONAL PASS）
- 定位：Unsupervised／Weakly Supervised 統計異常偵測**原型**。沒有任何偵測器通過事先凍結的升級準則，**不得稱 Validated**；Isolation Forest 因不比最簡單基準穩定而不保留。
- Holdout（2026-08-24 ～ 09-28）警報負擔：Robust Z 平均警報小時占比 0.382%。合成異常平均偵測率（**不是真實故障辨識能力**）：rule_based 0.59、robust_z 0.39、iforest 0.21。

**偵測器 v2**（Phase 5.8.7，`phase5_8_7/phase5_8_7_report.md`）——留存驗證 1,120 個合成批次，凍結後只跑一次：

## 7　感測器疑似故障守門與模型維護（Phase 5.8.9、5.9）

問題：目標感測器自己漂移時，78% 仍被建議重新訓練——重訓會把故障學進去。作法：在凍結的監測／重訓程式「外面」加一層守門，優先檢查資料品質；狀態不是「正常」時建議改為「先處理資料」，並擋下重訓（操作者可填寫至少 8 個字的原因覆寫，並寫入事件紀錄）。規則事先固定、沒有可調參數；凍結後留存集（540 個合成 cell，與以往不同種子）只執行一次：

| 留存結果（合成資料） | 故障類（300） | 真實改變類（240） |
|---|---|---|
| 守門攔下率 | **84.3%** | 10.0%（被誤攔） |
| 守門前建議重訓 | 66.3% | 52.5% |
| 守門後建議重訓 | **11.0%** | 45.8% |

仍無法處理：雜訊變大（35% 漏掉）與缺值／斷線（42% 漏掉）；真實改變會被誤攔 10%；14 天窗口與警報種類清單是**未經真實資料驗證的工程規則**。

## 8　決策輔助（Phase 6.4）

三層：`general`（資料檢查、監測、模型適用性）、`needs_human_review`（候選異常，**不是故障判定**）、`formal_risk`（只來自已登錄的正式決策引擎，目前**只有羊舍**，且門檻 84 仍是候選）。每項建議都帶可追溯的證據編號、可信程度（只代表「資料中確實出現所述現象」的把握，不是對故障或未來的把握）、限制與適用條件。硬性規則：不創造警戒門檻、不下故障結論、不產生自動控制、資料不足時不顯示預測值。Gemini 只改寫白話，核對失敗改回規則層原文。
