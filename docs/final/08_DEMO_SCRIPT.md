# 08　競賽展示操作腳本（約 10～12 分鐘）

> 展示對象：指導老師與競賽評審。全部使用**真實資料（探索）＋合成資料流（示範流程）**，不連接任何現場設備、不控制任何設備。
> 這份腳本以 **AI Studio App＋本機 Python 引擎（經免費 Quick Tunnel）** 為主；原始 Streamlit 研究平台（本機）是備案。

## 開場必講的三件事（30 秒）

1. 「七個場域的**原始資料是真實的**（競賽方提供）；『即時預測』和『資料更新』用的新資料是**合成（模擬）資料**，用來示範新資料進來時系統怎麼反應。」
2. 「展示情境是**我們挑選過的**，為了前後對照清楚，**不是偵測器的效能證明**。我們的預測結果是探索性回測，**沒有獨立盲測，所以不稱已驗證**。」
3. 「系統**不控制任何設備**；建議只有『檢查、確認、通知』，由人決定。」

## 0　展示前準備（建議前一晚做一次，展示前 30 分鐘再確認）

| 步驟 | 動作 | 應該看到 |
|---|---|---|
| 1 | `cd demo_kit && ./preflight.sh` | 全部通過 |
| 2 | `./start_local.sh`（想在現場看到自動更新：`./start_local.sh --interval 120`，**展示後改回預設 900**） | 引擎＋Caddy 啟動；只綁 127.0.0.1:8088；唯讀驗證通過。**換過金鑰後第一次啟動會產生新金鑰** |
| 3 | `./start_tunnel.sh`，**親自輸入確認句**「我了解這是臨時公開網址」 | 印出 `https://….trycloudflare.com`；公開側驗證通過 |
| 4 | AI Studio → Settings → Secrets：`ENGINE_BASE_URL`＝上面網址（結尾不加斜線）、`ENGINE_API_KEY`＝`./copy_key.sh` 複製後貼上；按 **Apply changes** | — |
| 5 | 開 App 網址 `/api/health` | `engine_connected: true`、`live_writes_enabled: false` |
| 6 | 開 App，逐一點七個場域的「即時預測」 | 六個場域各 15 組預測；育成一廠北側顯示「此場域不提供預測」 |
| 7 | 把瀏覽器縮放 110～125%，側邊欄展開 | — |

**備案準備**：先截圖保存「即時預測」「決策輔助」「資料更新」三個畫面；備好 [`remote_acceptance_report.md`](../phase6/remote_acceptance_report.md)（七場域驗收表）。Tunnel 預設 4 小時後自動關閉，展示時段要算進去。

## 1　總覽：資料是什麼、哪裡來（1 分鐘）

- 畫面：**總覽**（七場域環境監測總覽）。
- 說：「七個場域：羊舍、專家系統（魚塭）、三爺宮溪（河川水質）、工地微氣候、東北角、育成一廠與北側。列數從 387 到 2,881。」
- 點「資料來源與使用聲明」（進階）：說「資料由競賽方提供、沒有公開下載網址；**授權目前只有我們的使用者聲明**，沒有標準開放授權。」
- 指出：真實資料與合成資料在介面上永遠分開標示。

## 2　即時預測：資料流進來，預測自己更新（2.5 分鐘）

- 畫面：**即時預測**，場域選「羊舍」。
- 指橫幅：**「合成資料」**、「僅接受 Python 引擎即時回應，不用離線預計算檔取代」。
- 說：「引擎每隔一段時間（預設 15 分鐘＝1 個模擬小時）收到一筆合成新資料：暫存 → 提交 → 重算最新前向預測 → 監測。畫面每 30 秒讀一次狀態。」
- 指版本號與資料終點。**若用 `--interval 120` 準備**：停在這裡等一兩分鐘，版本（例如 羊舍-v0014 → v0015）與資料終點會自己前進，不需要重新整理。
- 說（誠實）：「這是**合成資料流**，示範流程；目前沒有接任何真實現場設備。」
- 切到「育成一廠北側」：說「這個場域只有 17% 的小時有讀值，**系統不強行建模，也不借用其他場域的模型**，所以不顯示預測。這是刻意的。」

## 3　決策輔助：每個建議都有依據（2.5 分鐘）

- 畫面：**決策輔助**，場域「專家系統」（有 26 條建議，最能展示分層）。
- 指頂端來源標示：**「引擎即時」**與產生時間。
- 三層：「一般建議／需要人工確認的異常／正式風險決策」。說：「**只有羊舍有正式風險決策，而且門檻 THI 84 仍是候選，不是確認標準。**」
- 點開一條「需要人工確認」：指**證據編號、可信程度、限制**；指「**候選事件，不是故障判定**」。
- 說：「可信程度只代表『資料中確實出現這個現象』的把握，不是對設備是否故障的把握。系統規則上**不能創造門檻、不能下故障結論、不能產生控制指令**，這些由程式強制，不是靠提示詞。Gemini 只負責把文字改寫得好懂，不產生建議。」
- 若評審問 Gemini：「展示時沒有設定金鑰，走規則式降級並標示『非 AI 生成』；真實 Gemini 我們沒有實測。」

## 4　資料更新：新資料來了，系統怎麼反應（2.5 分鐘）

- 畫面：**資料更新（合成展示）**，場域「羊舍」。
- 依序操作：**① 驗證 D2（不寫入）** → 看驗證報告 → **② 核准並寫入新版本（展示）**。
  - D2（環境改變：熱浪）：說「這是真實的現場變化，**不是**故障，所以不發故障警報。」
- 再做 **D3、D4（感測器緩慢漂移）**：
  - 說：「D3 剛開始偏，很難看出來——**七個場域中有 4 個如實漏報**（專家系統、三爺宮溪、工地微氣候、育成北側）；D4 累積到夠大才發現。」
  - 指「守門」：建議變成**『先處理資料』，重新訓練被擋下**。說：「感測器壞掉時重訓會把故障學進模型，所以擋下。」
  - 若問準確度：「合成留存驗證裡守門攔下 84.3% 的故障情境，但也誤攔 10% 的真實改變，雜訊變大與斷線仍漏掉 35%／42%（**合成資料，不是真實現場能力**）。」
- **D5（卡值與斷線）**：發現資料品質問題。
- 說：「步驟結果是原研究平台逐步匯入後的**預計算輸出**；頁面逐步呈現，不是在瀏覽器裡即時訓練。」
- 切到「育成一廠北側」做同樣頁面：顯示「**此場域不建立預測模型，沒有守門建議**」說明（曾經的崩潰缺陷 F13 已修正）。
- 回復：用版本表「回復到版本」回到先前版本，說「回復不刪除任何版本。」

## 5　研究誠實性：我們怎麼評估模型（1.5 分鐘，可口頭、配 [03](03_MODELS_RESEARCH_AND_VALIDATION.md) §3）

- 「羊舍 3 小時後 THI 預測：Holdout MAE，持續性 1.493、昨天同時刻 1.241、同小時平均變化 0.975、HGB 0.924、XGBoost 0.902（單位 THI）。」
- 「**但**模型比『同小時平均變化』只好約 5%，信賴區間含 0——它主要學到日夜週期。我們把這件事寫在報告裡。」
- 「加了風險感知後，預測區間覆蓋率從 0.865 校正到 0.900；高 THI 漏報率 0.307 降到 0.078，**代價是誤報率 0.093 升到 0.261**。」
- 「LSTM 與其他改良都沒有通過我們**事先宣告**的保留標準，所以正式模型維持不變——這也是結果。」

## 6　收尾（30 秒）

- 「資料進來 → 先確認資料可靠 → 再看預測與比較 → 每個結論附依據與限制 → 由人決定。」
- 「下一步最重要的是**前瞻驗證**：拿新資料、不重訓、直接預測。」

## 評審可能問（建議答法）

| 問題 | 回答 |
|---|---|
| 這是真實資料嗎？ | 七場域原始資料是真實的（競賽方提供）。即時預測與資料更新的新資料是**合成的**，每個畫面都標示；引擎內建的資料流也帶 synthetic 標記。**沒有連接任何真實現場設備。** |
| 預測準不準？ | 在羊舍 36 天資料上，3 小時預測贏過持續性與昨天同時刻，但主要來自日夜週期；全部是探索性回測，沒有盲測。其他場域 XGBoost 與 HGB 分不出勝負；通用基準研究中，105 個任務只有 23% 的 ML 達到預先登記的勝出條件。 |
| 偵測準確嗎？ | **沒有真實故障標籤，所以算不出真實準確率。** 合成留存驗證（1,120 批次）：precision 0.63、正常資料 FPR 1.6%、資料品質 recall 0.93、異常訊號 recall 0.67——僅描述偵測器在合成產生器上的表現。 |
| 會控制設備嗎？ | 不會。所有處置都只是建議或模擬紀錄。 |
| 為什麼育成北側沒有預測？ | 只有 17% 的小時有讀值、連續區段很短，低於我們事先凍結的最低觀測比例 60%。系統拒絕建模，也不借用別的場域。 |
| 為什麼不自動重新訓練？ | 重訓永遠由人決定；感測器疑似故障時擋下，避免把故障學進去；新舊模型要並排比較、可回復。（目前版本的重訓／啟用按鈕停用，因為需要寫入端點。） |
| THI 84 是標準嗎？ | **不是**，是候選分析門檻（也做過 83／85 敏感度），沒有經資料提供者確認。 |
| 為什麼用 Cloudflare Tunnel？ | AI Studio 在雲端，連不到本機。Quick Tunnel 免費、不需帳號，但是**臨時公開網址**、只供測試；我們用 API 金鑰＋唯讀＋Caddy 只轉送特定路徑保護，且展示後關閉並換金鑰。 |
| 能上線給真的現場用嗎？ | 還不行：需要前瞻驗證、門檻與單位確認、正式部署（自己的網域與認證）。見 [07](07_LIMITATIONS_AND_FUTURE_WORK.md)。 |
| 資料可以公開嗎？ | 我們只有使用者聲明（本競賽專題範圍），沒有標準開放授權；因此 GitHub repo 維持 private。 |

## 備案

| 狀況 | 做法 |
|---|---|
| 引擎或網路出問題、`engine_connected:false` | App 不會當機：決策輔助改用預計算結果（標示「預計算（離線）」）；即時預測頁顯示「尚未連線」。口頭說明這是設計好的降級，**不會拿預計算檔冒充即時預測** |
| Secrets 值變成範例文字 | 手動重填 `ENGINE_BASE_URL`、`ENGINE_API_KEY`，按 Apply changes（見 [05](05_OPERATIONS_MANUAL.md) §3） |
| Tunnel 到期（4 小時） | 重開 `./start_tunnel.sh` 並更新 `ENGINE_BASE_URL`（網址會變） |
| 現場完全無法連線 | 展示截圖與 [遠端驗收報告](../phase6/remote_acceptance_report.md)；總覽、資料探索、資料更新不依賴引擎，仍可現場操作 |
| 想展示原始研究平台 | 本機 Streamlit：`bash tools/p61_start_demo.sh`（在原研究專案資料夾；只綁 127.0.0.1:8501），操作流程見原專案 `docs/DEMO_SCRIPT.md` |

## 展示後收尾（2 分鐘）

```bash
cd demo_kit
./stop_demo.sh                  # 關 Tunnel、停容器；不刪資料
rm ~/aide-demo/state/demo.env   # 換金鑰：下次 start_local.sh 會產生新金鑰
docker ps; pgrep -af cloudflared; ss -ltn | grep 8088     # 三者都應該沒有輸出
```

若用過 `--interval 120`，下次啟動請改回 `./start_local.sh --interval 900`。
